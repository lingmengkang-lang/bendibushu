## 1. Modbus 0基/1基偏移（🔴 必须核 / 强化表述）

这是工控现场**最高频的坑**，也是本工程多处样例的核心风险点：

### 1.1 🔴 组态王 kingview.md：示例 `D100（保持 40101）` 暗含假设
- **问题**：表格把 `D100` 直接标成 `保持 40101`，这**暗含"D0 = 40001"的 1基假设**。但：
  - Modbus 协议层面，保持寄存器**协议地址是 0 基**（0x0000 起），**人读编号是 1 基**（40001 起）。`40101` = 协议寄存器号 `100`。
  - **D100 是否等于寄存器 100，完全取决于该 PLC 的 Modbus 映射表**。以三菱 FX5U 为例，其 Modbus 保持寄存器映射里 D 区的起始偏移是按"软元件 Modbus 地址"参数设定的，**默认并不等于 D0=40001**；很多日系 PLC 把 D0 放在 4xxxx 的某一段而非紧挨 40001。
- **结论**：示例本身打了"示意/必须人工核对"的注，方向对；但**必须显式写出"本例假设 D0↔40001（1基），实际以你所用 PLC 的 Modbus 映射表为准"**，否则新人会照抄 `D100=40101` 直接下。
- **处置**：建议把这一句从脚注提升为正文醒目提示。

### 1.2 🔴 力控 forcecontrol.md：`线圈 1 / 线圈 2` 歧义
- **问题**：点表写"线圈 1""线圈 2"，未说明是 1 基（00001/00002）还是 0 基（0/1）。力控/驱动配置里这两种填法都会见到，混用会**整段错位**。
- **结论**：必须写成 `00001（1基）` 或 `0（0基）` 并注明基准。同文件"保持 40100/40101"是 1 基写法，建议统一声明基准。

### 1.3 🟡 EBPro weinview.md / MCGS mcgs.md：`4x/3x/0x` 内部再 -1 的坑
- 两文档都已写明"实际通信地址还要减 1 或按设备定义，务必实测"，且列为红线。**方向正确**。
- **建议**：在每处 `4x0001` 示例后统一补一句"EBPro/MCGS 内部地址与 Modbus 协议地址可能差 1，下装前用变量监视对照真机实测"，强化肌肉记忆。

## 2. 各品牌脚本语法准确性（逐一评）

### 2.1 组态王 kingview.md
- 🟡 `mod($Second, 2)`：**组态王命令语言是类 C 语法，取模用 `%` 更通用**，`mod()` 并非所有版本都内置。建议改为 `$Second % 2`，并把"函数名随版本"的注从脚注提为正文。
- 🟡 字符串连接 `"$Year + \"-\" + $Month + ..."`：版本差异大，部分版本用 `StrCat` 或 `+` 行为不同。**建议注明"字符串连接运算符以你版本手册为准"**（现状仅泛注，已可接受，强化即可）。
- 🟢 变量引用 `\本站\变量名`、命令语言分"数据改变/事件/定时"分类：**准确**，与组态王实际一致。
- 🟢 互锁/弹窗逻辑（先查故障再启动）：**正确且符合现场规范**。

### 2.2 西门子 WinCC wincc.md
- 🟢 `HMIRuntime.Tags("X").Read / .Value`：经典 VBS 写法，**准确**。
- 🟢 `SmartTags("X").Value`（V7.2+）：**准确**。
- 🟡 关键写操作建议显式 `.Write`：`HMIRuntime.Tags("MotorStart").Value = True` 之后若依赖刷新周期下发，按钮响应会慢半拍。对启停这类关键命令，**建议显式调用 `.Write`** 立即下发（读也显式 `.Read` 取最新值）。
- 🟢 "累加/联锁逻辑放 PLC 侧，HMI 只显示与下发"：**非常正确**，是现场推荐的分工，文档已强调。
- 🟢 DB 偏移必须与 PLC 符号表一致、否则显示 `####` 旧值：**准确且关键提醒到位**。

### 2.3 昆仑通态 MCGS mcgs.md
- 🟢 `!` 前缀函数（`!SetWindow`/`!SetDevice`/`!Sleep`）及"名称/参数各版本不一致，核对脚本函数手册"：**准确**，`!` 是 MCGS 脚本的硬性约定。
- 🟡 `!SetDevice(0, "Write", "1号频率给定", 设定频率)` 的参数结构：真实 MCGS `!SetDevice` 写入是按"设备句柄 + 通道名/编号"，示例把"设备索引 0"与"变量名字符串"混用作参数，**属于逻辑示意而非可直接套用的精确签名**。建议在该行加"参数顺序/个数以你版本设备构件为准"，避免直接复制报错。
- 🟢 纯 `if/while/for` 与变量赋值稳定可用：**正确**。
- 🟢 "两处地址都要核对：设备构件属性 + 实时数据库通道"：**切中要害**，是 MCGS 最高频错误。

### 2.4 威纶通 EBPro weinview.md
- 🟡 `GetData(0x0003, 1)` / `SetData(0x0010, 1)`：EBPro 宏的 `GetData/SetData` **参数形式（是否带数据类型、返回值处理）各版本差异明显**，文档已注明"先在测试窗口跑通一个读写再扩展"。**方向对，建议把"先单机测试窗口验证"从注提升为步骤 0**。
- 🟢 频率给定 `0~500` 对应 `0~50.0Hz`（1 位小数）范围校验：**正确且是防呆好习惯**。
- 🟢 `4x/0x` 偏移"差 1 就全偏"列为红线：**准确**。

### 2.5 力控 ForceControl forcecontrol.md
- 🟡 变量引用（`AO01 = 0`、`IF DI02 == 1`）：力控脚本变量引用方式（直接点名 / `#点名` / 函数取值）**随版本与配置不同**，文档已注明"先测试画面验证变量读写通不通"。**建议补充一个最小验证脚本示例**（读一个点、写一个点的回环），比纯文字更落地。
- 🟢 计算点掉电清零、存盘周期按磁盘估算、安全保护由 PLC/硬件兜底：**均为现场真经验，准确**。

## 3. 上位机写入校验 / 轮询 / 超时（🔴 必须加模板）

`docs/host/README.md` 已有红线（写入校验、轮询控制、软互锁不替代硬急停、先只读后写），**方向正确但缺可落地的代码模板**。20 年现场经验里，上位机出事大多栽在三点：

1. **写入无边界校验** → 误写超范围值触发设备误动作；
2. **无超时/异常** → 设备掉线时界面卡死或雪崩；
3. **轮询过密** → 串口/设备被问爆、通信抖动。

**必须补一个"上位机写入安全模板"**（建议新增 `docs/host/write_safety_template.md`），包含：
- 写前范围/合法性校验（频率 0~50Hz、位置限位、压力上限）；
- `try/except` 包裹通信，设显式超时（如 500ms~1s），失败进入退避重连（指数退避，上限封顶）；
- 轮询下限：**串口 ≥ 100ms、以太网 ≥ 50ms**，批量读优于单点轮询；
- 关键命令（启/停）建议"写+回读确认"而非"写即信"。

C#（NModbus）/ Python（pymodbus）各给一段最小可运行骨架即可。这是把"红线"变成"默认动作"的关键一步。

## 5. 最终判定：必须改 / 建议改 / 可不改

### 🔴 必须改（消除歧义 / 防误用）
1. **kingview.md**：`D100（保持 40101）` 示例必须显式声明"假设 D0↔40001（1基），实际以各 PLC Modbus 映射表为准"，并把该提示从脚注提为正文。
2. **forcecontrol.md**：`线圈 1/2` 改为 `00001/00002（1基）` 或 `0/1（0基）` 并注明基准。
3. **docs/host**：新增"上位机写入安全模板"（校验+超时+退避+轮询下限+回读确认），把红线落成默认代码。

### 🟡 建议改（更稳 / 更通用）
4. kingview.md 取模 `mod()` → `$Second % 2`；字符串连接注明版本。
5. wincc.md 关键写操作显式 `.Write`。
6. mcgs.md `!SetDevice` 示例加"参数以版本为准"；weinview.md 把"先测试窗口验证读写"提为步骤 0。
7. 所有 `4x/3x/0x` 示例统一补"内部可能再 -1，下装前实测"一句话。

### 🟢 可不改（已充分，保持）
8. SAFETY.md 整体红线、WinCC"逻辑放 PLC"、MCGS `!` 约定、脱敏规范、力控掉电保持提醒——均符合现场实践，维持现状。
