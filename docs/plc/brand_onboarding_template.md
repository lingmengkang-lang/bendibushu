# 品牌 / 器件接入骨架模板（填空即可让 AI 自动部署）

> **用途**：你要新增一个 PLC 品牌、一个电气件、或一套自己的用法时，
> 复制本模板 → 填空 → 放进 `docs/devices/`（或 `docs/plc/`）→ 跑一次 `add-all`。
> 之后问 AI"按我新增的 XX 做一套工程/程序"，它就有据可依，不会再瞎编。
>
> **这就是"本地部署能不断增加应用场景"的机制**：不需要改代码，只需要加文档。

---

## 二、填好后的效果对比

| | 没填模板前 | 填好并 add-all 后 |
|---|---|---|
| 问 AI "汇川 MD290 的频率给定写在哪个寄存器" | 靠记忆猜，**可能编一个错地址** | 检索到你的映射表，给出你核对过的地址 |
| 让 AI 生成上位机读写程序 | 通用示例，地址要你逐个改 | 直接按你的映射表生成，可跑性高 |
| 新增一个品牌 | 改代码 / 改提示词 | **复制模板填空，一条 add-all** |
| 团队共享 | 口口相传 | 文档入库，全员检索一致 |

## 三、放哪里

| 内容类型 | 目录 | 说明 |
|---|---|---|
| 常用电气件（变频器/伺服/仪表/传感器） | `docs/devices/` | 一个器件一个 md |
| PLC 品牌资料 | `docs/plc/brands/<品牌>.md` | 与 `brands.md` 对照表配合 |
| 组态样例工程说明 | `docs/scada/` | 或新建 `docs/scada/<项目名>.md` |
| 上位机程序样例（脱敏） | `docs/host/` | 附寄存器分配表 |
| 你自己的手册 PDF | `data/knowledge_base/docs/` | **不要提交含密内容到 Git** |

> 新建目录后，记得把目录加进 `config/rag.config.json` 的 `knowledge_dirs`。

## 四、红线

- **第 3 节映射表必须人工核对**，这是整套机制的地基；错一个偏移，后面全歪。
- **脱敏**：真实 IP、账号、工艺参数、图纸不要提交进 Git 仓库。
- 模板里的"惯用做法"要写**为什么**，AI 才能在你不在场时做对判断。
- 涉及安全的保护（急停、限位）必须硬接线，文档里也要写明这一点。
